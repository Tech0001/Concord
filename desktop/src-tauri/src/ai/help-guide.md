Local recordings: Pipeline → Sources → Add folder → Browse, choose the directory, name/category, Save & scan folder. Scans include supported audio/video in subfolders. Saving queues new files but does not start a paused queue; use Queue → Start queue. The source's Scan folder rescans. Check the source result, folder availability (mounted external drive), and Personal/Work/Both filter when recordings seem absent. A successfully scanned empty folder can correctly yield zero recordings. Files explicitly removed from the library stay ignored by future scans; explicitly adding the file again restores it. Remove from library preserves original files; Move to Trash is a different action. Renaming/removing a source does not delete existing media. Source check limits are configured in Pipeline setup.

YouTube: optional and off by default. Enable/install the managed yt-dlp in Settings → YouTube downloads; Concord does not automatically use a system yt-dlp. Downloads come from its official repository after opting in. Pipeline → Sources → Add YouTube source → URL and name → Save source → Check now; Find full history discovers older entries. Downloads need FFmpeg. Automatic checks require an enabled source, automatic checks enabled in Pipeline setup, and a started pipeline. Daily download limits/retries may defer work. Existing local files imported separately are not guaranteed to match YouTube IDs.

Speech: Nemotron 3.5 multilingual transcription plus Nemotron diarization through NeMo-Speech.cpp. Persistent voice profiles use TitaNet. Settings → Speech → Prepare speech installs private dependencies/models; setup can continue during downloads. Automatic uses a supported GPU; CPU works on lower-spec machines. Voice matching itself uses CPU. Check again refreshes availability. Models present does not prove the runtime/FFmpeg/voice matching are ready. Install FFmpeg using the OS package manager when missing. Pending jobs can wait for speech installation; a failed install needs repair/retry before restarting the job. If memory is exhausted, close other GPU workloads or choose CPU and retry. A driver/runtime error requires checking Speech settings. Python 'encodings' errors concern the speech environment, not transcript content; use speech setup/repair and review Status & Health. Speaker capacity targets 16 via overlapping windows and voice matching; 11 speakers were observed in real testing, and an actual 16-person validation is still outstanding. Speaker labels are recording-local until mapped to profiles; multiple fingerprints can belong to one person. Use Speakers and the unidentified-voices queue or transcript speaker label to name/link a voice.

Documents: Docs has Add root folder and Sync now, for Markdown and plain text. It does not currently import PDF/Word. Live sync/indexing and semantic embeddings are separate. Diagram-only files may have nothing to embed. Missing folder availability can mean an unmounted drive.

Search: Search page finds exact words/phrases with source, date, speaker, collection and tag filters. AI → Semantic search finds meaning. Built-in Qwen3 Embedding is a separate 639 MB model, local and without a key. From 0.26, it uses Vulkan GPU automatically, or CPU when no GPU is supported. Its index shows actual offloaded layers. File parsing, exact-word indexing and CPU orchestration still use CPU even during GPU embedding. Use Prepare semantic search or Update index in AI/Settings. Stopping keeps completed sources; Update index resumes. CPU/GPU switching alone does not invalidate the index. Changing embedding models/vector spaces may require a fresh index; don't mix dimensions. No chat subscription is needed for semantic search. Off disables semantic search.

Chat: Settings → AI has separate embedding and chat providers/models/keys. Codex CLI and Claude Code CLI use installed, signed-in, unmodified CLIs. Sign in using codex login or claude auth login, then Test chat. The model value default uses the CLI's default; supported model IDs can be entered. Current CLI versions are needed. Subscription limits/extra-usage settings apply. OpenRouter needs its own key; local Ollama/LM Studio must be running; a custom OpenAI-compatible endpoint is also supported. Connecting chat does not require changing embeddings. Remote providers receive selected context. Concord help shares this guide and the filtered setup snapshot, not recordings, paths, secrets or raw logs. Ask in the top bar (Ctrl+J) opens the shared conversation beside the current page; Full view opens AI. The visible context choice defaults to Concord help on Settings/Setup/Status, This recording in the player, and My archive elsewhere; a draft keeps its chosen scope. My archive retrieves up to ten relevant passages and cites [1], [2]. Just chat adds no fresh archive/app context. This recording restricts retrieval and earlier model history to the selected recording. A standalone greeting skips retrieval. Conversation history shown in the app is unified; only earlier messages with the same context choice are sent to the model to avoid carrying diagnostics into archive/general requests. Pipeline: Queue shows queued/running/retry/failed work. Start queue, Pause, Stop and retry/cancel are distinct controls. Batch transcription can reprocess selected recordings while preserving previous transcripts until success. Optional automatic embeddings/summaries after transcription are separately enabled in Pipeline; existing recordings are not backfilled automatically. Failed AI processing doesn't undo transcription. Check source scan results, speech readiness and queue state before diagnosing a stuck job. Read-only diagnostics may be slightly old; ask the user to check the linked screen after a change.

Player: timestamps seek and play; pane divider resizes video/transcript. Speaker tint identifies the voice; amber highlights playback/selection. Transcript ranges can become notes, copied text or exported clips. Notes can contain multiple passages; Map links notes with typed relationships. Status & Health contains Status, Health & repair, Activity and Terminal. Run audit finds issues; Review inspects affected items; repairs and backups are user-triggered. Terminal is read-only app output. Backups contain database/research/settings, not large external media; restore is validated/staged and applied after restart. Tools provides Extract and Recorder. Appearance/font/theme options live in Settings.
