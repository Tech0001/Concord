Concord is a Linux-first Rust/Tauri preview. Its database is separate from Electron's. No Discover, Watchers or Compare. Existing speech hardware settings affect transcription, not embeddings. Setup is optional after choosing a library. Following a channel adds only videos posted after following, not its older videos; a document folder adds Docs, not Library recordings.

Adding: everything comes in through Add (top bar, or the empty Library). Drop audio or video files, or a folder, anywhere in the window; use Choose files or Choose folder; or paste links, several at once, one per line. Pasting a link outside a text field also opens Add. Before adding, choose Personal or Work and whether to identify speakers. Added recordings are transcribed by themselves, one after another; there is no Start step. Each recording's card shows Downloading, Waiting to transcribe, Transcribing or Needs attention. A folder adds the recordings it holds now, subfolders included; Keep watching this folder also adds recordings saved there later while Concord is open and lists the folder under Following in the sidebar. Files already in the library aren't added twice. Files explicitly removed from the library stay ignored by later checks; explicitly adding the file again restores it. Remove from library preserves original files; Move to Trash is a different action. Stopping following doesn't delete recordings already added. When recordings seem absent, check folder availability (a mounted external drive) and the Personal/Work/Both filter.

Links: optional and off by default. The first time a video, channel or playlist link is added, Add offers to install Concord's managed yt-dlp from its official repository (Install and continue); link downloads can be turned on or off in Settings → Downloads & Schedule. Concord does not use a system yt-dlp. A video link adds that video: downloaded, then transcribed. A channel or playlist link can only be followed for new videos: videos posted after following are downloaded while Concord is open, and nothing older is downloaded. To add an older video, paste its link. Followed channels appear under Following in the sidebar; each opens as a Library collection with its last check, Check now, and Options (Personal or Work, Identify speakers, Include Shorts, Rename, Stop following). Subscriptions from older versions appear on Activity as older subscriptions with Follow for new videos. Downloads need FFmpeg. Daily download limits, download pace, cookies, and retries are in Settings → Downloads & Schedule. Existing local files imported separately are not guaranteed to match YouTube IDs.

Speech: Nemotron 3.5 multilingual transcription plus Nemotron diarization through NeMo-Speech.cpp. Persistent voice profiles use TitaNet. Settings → Speech has the CPU/GPU device choice, transcription language, transcripts folder, readiness facts, and Prepare speech / Repair speech setup. Automatic uses a supported GPU; CPU works on lower-spec machines. Voice matching itself uses CPU. Check again refreshes availability. Models present does not prove the runtime/FFmpeg/voice matching are ready. Install FFmpeg using the OS package manager when missing. Pending jobs can wait for speech installation; a failed install needs repair/retry before restarting the job. If memory is exhausted, close other GPU workloads or choose CPU and retry. A driver/runtime error requires checking Speech settings and Activity → Logs. Python 'encodings' errors concern the speech environment, not transcript content; use speech setup/repair and review Activity → Status & Health. Speaker capacity targets 16 via overlapping windows and voice matching; 11 speakers were observed in real testing, and an actual 16-person validation is still outstanding. Speaker labels are recording-local until mapped to profiles; multiple fingerprints can belong to one person. Use Speakers and the unidentified-voices queue or transcript speaker label to name/link a voice.

Documents: Docs has Add root folder and Sync now, for Markdown and plain text. It does not currently import PDF/Word. Live sync/indexing and semantic embeddings are separate. Diagram-only files may have nothing to embed. Missing folder availability can mean an unmounted drive.

Search: the Search page has both Keywords (All words / Exact phrase) and By meaning modes, with source, date, speaker, collection and tag filters. Built-in Qwen3 Embedding is a separate 639 MB model, local and without a key. It uses Vulkan GPU automatically, or CPU when no GPU is supported. File parsing, exact-word indexing and CPU orchestration still use CPU even during GPU embedding. Use Build search index or Update search index right in Search → By meaning, Settings → AI & Search, or Activity → Status & Health. Stopping keeps completed sources; Update search index resumes. Indexing progress appears live in Activity → Queue → Now. CPU/GPU switching alone does not invalidate the index. Changing embedding models/vector spaces may require a fresh index; don't mix dimensions. No chat subscription is needed for semantic search.

Chat: Settings → AI & Search has separate Search & Embeddings, Chat & Summaries, and After transcription sections. Codex CLI and Claude Code CLI use installed, signed-in, unmodified CLIs. Sign in using codex login or claude auth login, then Test chat. The model value default uses the CLI's default; supported model IDs can be entered. Current CLI versions are needed. Subscription limits/extra-usage settings apply. OpenRouter needs its own key; local Ollama/LM Studio must be running; a custom OpenAI-compatible endpoint is also supported. Connecting chat does not require changing embeddings. Remote providers receive selected context. Concord help shares this guide and the filtered setup snapshot, not recordings, paths, secrets or raw logs. Ask in the top bar (Ctrl+J) opens the shared conversation beside the current page; Full view opens AI. The visible context choice defaults to Concord help on Settings/Setup/Activity, This recording in the player, and My archive elsewhere; a draft keeps its chosen scope. My archive retrieves up to ten relevant passages and cites [1], [2]. If no semantic index is built yet, Ask Concord automatically falls back to keyword search and offers a one-click Build search index button on the reply. Just chat adds no fresh archive/app context. This recording restricts retrieval and earlier model history to the selected recording. A standalone greeting skips retrieval. Conversation history shown in the app is unified; only earlier messages with the same context choice are sent to the model to avoid carrying diagnostics into archive/general requests. Activity: one tabbed workspace with Queue, Status & Health, Logs, and Backups. Queue shows Now (including live downloads, transcription, semantic indexing, and repairs), Needs attention (Retry, Ask for help, Remove), Up next, Following (Check all now), Automatic AI, and History. One Pause/Resume holds new recording work, and what is running finishes first. To transcribe existing recordings again, select them in the Library and choose Transcribe in the selection bar; previous transcripts stay until the new one succeeds. Status & Health shows archive coverage cards (with direct Build / Update search index buttons), channels table, Run health audit, Embedding compatibility guard, and repairs. Logs shows the live Activity / Debug terminal and Runtime diagnostics. Backups creates database backups and validates/stages restores applied after restart.

Player: timestamps seek and play; pane divider resizes video/transcript. Speaker tint identifies the voice; amber highlights playback/selection. Transcript ranges can become notes, copied text or exported clips. Notes can contain multiple passages; Map links notes with typed relationships. Record is in Add and Extract audio is on each recording's menu; both open Tools. Appearance, Library info, and About live in Settings → General.
